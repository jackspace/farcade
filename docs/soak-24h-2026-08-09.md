# P6.4 — the 24-hour soak, the Windows host ↔ the Pi over prnsd

Ran 2026-08-09 ~01:25 to 2026-08-10 ~01:27 CST. Completed on schedule. Raw evidence:
`soak-24h-final-a.json` and `soak-24h-final-b.json` beside this doc (both initiators'
`final.json`, verbatim); per-message CSVs stay on the bench (`.local/soak-24h*/events.csv`).

## Topology under test

Initiator (the Windows host, Windows) → **prnsd 0.3.3 release binary as shared instance and transport
node** → TCPClientInterface → the Pi (Pi4, aarch64) standalone Python RNS → responder.
Every message crossed the Rust stack. Initiators paced one move per 60 s (`SoakRunner`);
responder answered instantly with random legal moves.

## The accident that improved the experiment

The design was one initiator. A command meant to stop the first initiator (launched 01:22)
and restart it with an added `rpc_key` was refused by the local permission layer — and a
refused command executes NONE of its parts, including the stop. Result: the first initiator
kept running, a second launched at 01:27, and **two independent 24 h sessions ran
concurrently against one responder**. The session layer is keyed by game id, so this
exercised multi-session concurrency a day-one design had deferred to tier 2 — by mistake,
with clean results. (Lesson banked: after any permission refusal, re-verify every side
effect the command was supposed to have.)

## Results — two independent 24 h datasets

| metric | run A (01:22) | run B (01:27) |
|---|---|---|
| games | 106 started, all finished | 137 started, all finished (136 wins, **1 board-full draw**) |
| initiator moves | 1,194 | 1,437 |
| messages logged | — | 3,073 (1,574 out / 1,499 in) |
| duplicates / gaps / desyncs | **0 / 0 / 0** | **0 / 0 / 0** |
| syncs needed | 0 | 0 |
| dropped sends | 0 | 0 |
| turn latency median | **0.206 s** | **0.204 s** |
| turn latency max | 28.7 s | 55.7 s |
| longest silence | 120.2 s | 62.9 s |

The responder's own counter closed at 247 games served across the bench day (both runs plus
earlier smokes), 0 dropped sends, while multiplexing both correspondents the whole time.

## Anomalies, each attributed

1. **One draw ("board full") in 243 games.** Random connect four draws roughly once per
   ~150 games; one is the expected value showing up — a validity check, not a defect.
2. **~1% of turns took 12–56 s** (11 of 1,362 in run B; scattered 10:06–23:07, no
   clustering). Every one arrived in order; the protocol layer saw no duplicate, no gap,
   and never requested a sync. Consistent with occasional single-packet loss healed by RNS
   retransmission below our protocol; not consistent with any session-layer failure.
3. **Both 24 h runs were rpc_key CONTROL arms.** The `rpc_key` fix (see
   topology-prnsd.md) was meant to be in run B's config; the refused command above meant
   neither run had it. Run B logged **9,387** `digest sent was rejected` stats-RPC errors
   across the day — and still delivered every message with 204 ms median latency and zero
   protocol events. So the 24 h scale point is the control: the wart is noisy but harmless
   to delivery. The fix itself is verified in the short arm (same workload, key present,
   zero errors).
4. **The watchdog's final event said "SOAK DEAD".** The initiator exits after writing
   `final.json`; the watchdog's PID check won the race against its completion check. The
   artifact on disk is the truth. Future monitors: check the completion artifact first.
5. **Run A's 120 s longest silence** is two pacing intervals — one skipped beat where its
   straggler (max 28.7 s) pushed a reply past the next pacing tick. No outage.

## Verdict

P6.4 acceptance ("completes or is explained; every anomaly attributable") is met, and the
sprint-1 verification list is complete through P6. Over 24 unattended hours, across two
concurrent sessions, the session core needed **zero** of its healing machinery — no resync,
no dedup, no divergence repair — while the instrumentation proved it was measuring (the
same columns go red on injected faults in `tests/test_instrument.py`).

## Residue

- prnsd still runs on the Windows host (radios off, TCP link to the Pi now dark). Harmless; reused by
  future Farcade work.
- `~/farcade-soak/` on the Pi holds the responder venv and artifacts; responder stopped,
